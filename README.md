# Samika (سامیکا)

نمونهٔ قابل اجرا برای دورهمی آنلاین با چت، صدا، تصویر، اشتراک صفحه، واکنش‌های زنده، بازی گروهی و پخش همگام ویدئو. امکان نصب روی دستگاه هم دارد. تهیه‌شده توسط **سام کاظمی**.

زبان پیش‌فرض فارسی است. از فهرست زبان‌ها می‌توان انگلیسی، ترکی استانبولی، عربی یا فرانسوی را انتخاب کرد. انتخاب زبان در همان مرورگر ذخیره می‌شود.

## نسخهٔ آنلاین

- سایت اصلی و سرور تماس: <https://samika.onrender.com>
- نسخهٔ GitHub Pages: <https://samkazemii.github.io/samika/>
- زیردامنهٔ کوتاه پیشنهادی: `samika.is-a.dev` (پس از تأیید درخواست و افزودن دامنه در Render فعال می‌شود).

هر دو نشانی از سرور تماس Render استفاده می‌کنند. سرویس رایگان Render پس از مدتی بی‌استفاده‌بودن به خواب می‌رود؛ اولین ورود بعد از آن ممکن است چند ده ثانیه طول بکشد.

### اتصال زیردامنهٔ رایگان `samika.is-a.dev`

ثبت این زیردامنه رایگان است، اما قطعی و فوری نیست: مخزن is-a.dev باید درخواست را بپذیرد و نام هم باید آزاد باشد. راهنمای رسمی Render در is-a.dev می‌گوید فایل `domains/samika.json` با این محتوا به‌صورت pull request ارسال شود:

```json
{
  "owner": { "username": "samkazemii" },
  "records": { "A": ["216.24.57.1"] }
}
```

پس از ادغام درخواست، در Render به سرویس Samika بروید و از **Settings → Custom Domains** مقدار `samika.is-a.dev` را اضافه و تأیید کنید. Render گواهی HTTPS را خودکار صادر می‌کند. تا قبل از تأیید is-a.dev و اتصال در Render، نشانی فعلی `samika.onrender.com` نشانی فعال است.

## اجرا روی رایانه

Node.js نسخهٔ ۲۰ یا جدیدتر لازم است. در پوشهٔ پروژه اجرا کنید:

```bash
npm install
npm start
```

اگر `pnpm` دارید، معادل آن `pnpm install` و `pnpm start` است.

سپس `http://localhost:3000` را در مرورگر باز کنید. هر نفر هنگام ورود نام کاربری وارد می‌کند. همهٔ اتاق‌ها خصوصی و دارای لینک دعوت تصادفی هستند؛ فهرست عمومی اتاق‌ها وجود ندارد. لینک دعوت را فقط برای افراد مورداعتماد بفرستید، چون هرکس لینک را داشته باشد می‌تواند وارد شود.

اتاق‌های اخیر در همان مرورگر ذخیره می‌شوند؛ خروج از اتاق آن را از فهرست اخیر حذف نمی‌کند. اتاق‌های خالی روی سرور تا ۷ روز نگه داشته می‌شوند، اما با راه‌اندازی مجدد سرویس، وضعیت موقت بازی و ویدئوی درحال‌پخش ممکن است پاک شود. لینک دعوت و نام اتاق در آدرس باقی می‌ماند؛ اتاق همچنان خصوصی و فقط با لینک قابل دسترسی است.

برای تماشای هم‌زمان، لینک HTTPS مستقیم MP4/WebM یا لینک YouTube را در نوار ویدئوی اتاق وارد کنید. اولین فردی که وارد اتاق می‌شود ادمین است؛ فقط ادمین‌ها می‌توانند ویدئو را بارگذاری، پخش، متوقف، جلو/عقب یا ببندند. ادمین می‌تواند با کلیک روی کارت هر عضو او را هم ادمین کند. اگر آخرین ادمین خارج شود، یکی از اعضای باقی‌مانده ادمین می‌شود. ویدئوی مشترک و تصویر دوربین/صفحه از دکمهٔ تمام‌صفحه قابل بزرگ‌کردن است؛ در iPhone و مرورگرهایی که تمام‌صفحهٔ بومی ندارند، سامیکا حالت تمام‌صفحهٔ جایگزین دارد. برای تماس زنده، هر نفر دکمه‌های میکروفن/دوربین را بزند و اجازهٔ مرورگر را بدهد. برای شیر اسکرین در رایانه، مرورگر پنجرهٔ انتخاب منبع را باز می‌کند؛ آنجا تب ویدئو، پنجرهٔ برنامه یا کل صفحه را انتخاب کنید. برای فرستادن صدای ویدئو معمولاً باید تب مرورگر را انتخاب کرد. ارسال صدای صفحه به مرورگر و منبع انتخاب‌شده بستگی دارد؛ صدای اپ‌های دیگر مثل Instagram ممکن است در گوشی به مرورگر داده نشود. در این حالت، میکروفن سامیکا را روشن کنید و گوشی را روی بلندگو بگذارید، یا لینک ویدئو را مستقیم داخل سامیکا پخش کنید. سامیکا نمی‌تواند پخش‌کنندهٔ ویدئویی را که در برنامه یا پنجرهٔ دیگری شیر شده از راه دور کنترل کند؛ کنترل پخش و جابه‌جایی فقط برای ویدئوی بارگذاری‌شده در خود سامیکا است.

واکنش‌های 😂 😭 ❤️ 😮 🔥 👏 در اتاق برای همه پخش می‌شوند. از دکمهٔ بازی 🎮 می‌توان دوز آنلاین، حدس عدد و چالش‌های نوبتی را شروع کرد.

برای نصب، سایت باید با HTTPS باز شود. در Chrome/Edge از دکمهٔ **نصب** استفاده کنید. در iPhone/iPad با Safari دکمهٔ **اشتراک‌گذاری → افزودن به صفحهٔ اصلی** را بزنید؛ ممکن است Safari پنجرهٔ نصب خودکار نشان ندهد.

## انتشار با GitHub و Render

GitHub محل نگهداری کد است؛ GitHub Pages به‌تنهایی نمی‌تواند سرور WebSocket این پروژه را اجرا کند. برای اینکه اتاق‌ها از دستگاه‌های مختلف به هم وصل شوند، پروژه را روی یک سرویس Node.js مثل Render اجرا کنید.

۱. یک مخزن GitHub به نام دلخواه بسازید و **محتویات این پوشه** را در ریشهٔ مخزن قرار دهید (`index.html`, `app.js`, `i18n.js`, `server.js`, `package.json`, `render.yaml`, `.nojekyll`).

۲. در ترمینال همان پوشه، نشانی مخزن خودتان را جایگزین کنید:

```bash
git init
git add .
git commit -m "Build Samika hangout"
git branch -M main
git remote add origin https://github.com/USERNAME/samika.git
git push -u origin main
```

۳. در Render گزینهٔ **New → Blueprint** را انتخاب و مخزن را متصل کنید. فایل `render.yaml` فرمان نصب و اجرا و مسیر بررسی سلامت سرویس را تنظیم می‌کند. پس از انتشار، نشانی HTTPS سرویس را باز کنید؛ WebSocket به‌صورت خودکار روی WSS وصل می‌شود.

برای آزمایش دو نفره، لینک دعوت را از یک مرورگر کپی کنید و در دستگاه یا پروفایل مرورگر دیگری باز کنید. هر دو نفر باید به همان نشانی منتشرشده وصل باشند.

## تنظیم TURN برای شبکه‌های محدود

پروژه یک نشانی STUN عمومی دارد. در بعضی شبکه‌ها یا پشت بعضی فایروال‌ها، STUN به‌تنهایی کافی نیست و تماس به TURN نیاز دارد. سرویس TURN خودتان را تهیه کنید و پیش از `<script src="app.js"></script>` در `index.html` تنظیم کنید:

```html
<script>
  window.SAMIKA_RTC_CONFIG = {
    iceServers: [
      { urls: "stun:stun.l.google.com:19302" },
      {
        urls: "turn:TURN_HOST:3478",
        username: "SHORT_LIVED_USERNAME",
        credential: "SHORT_LIVED_CREDENTIAL"
      }
    ]
  };
</script>
```

اعتبارنامهٔ دائمی TURN را در کد عمومی GitHub قرار ندهید؛ از اعتبارنامه‌های کوتاه‌عمر ارائه‌دهنده استفاده کنید.

## محدودهٔ این نسخه

- سرور سیگنالینگ و چت زنده در `server.js` قرار دارند؛ صوت و تصویر ویدئویی با WebRTC بین مرورگرها منتقل می‌شود.
- اشتراک صفحه با `getDisplayMedia` انجام می‌شود و ترک صوتی انتخاب‌شده جداگانه با WebRTC فرستاده می‌شود. مرورگر می‌تواند بدون ترک صدا پاسخ دهد؛ گرفتن صدای اپی دیگر (از جمله Instagram) روی گوشی تضمین‌شده نیست.
- واکنش‌ها و وضعیت بازی در همان اتاق با WebSocket همگام می‌شوند. کد اتاق‌های اخیر فقط در حافظهٔ مرورگر همان دستگاه ذخیره می‌شود.
- فایل‌های manifest، آیکن و service worker نصب PWA و بازشدن پوستهٔ صفحه در حالت آفلاین را فراهم می‌کنند. تماس، صدا، تصویر و همگام‌سازی بازی همچنان به اینترنت نیاز دارند.
- انتقال همتا‌به‌همتا برای اتاق‌های کوچک تا ۸ نفر طراحی شده است. نرخ ویدئوی ارسالی برای محدودکردن مصرف پهنای‌باند تنظیم می‌شود، اما کیفیت همچنان به سرعت آپلود و شبکهٔ هر عضو بستگی دارد. در شبکه‌های محدود، TURN لازم است؛ اتاق‌های بزرگ‌تر به سرور رسانه‌ای SFU هم نیاز دارند.
- کارت‌های لابی فقط ایده‌اند و هرکدام یک اتاق خصوصی تازه می‌سازند. فهرست عمومی زنده، حساب کاربری و احراز هویت در این نسخه پیاده‌سازی نشده‌اند.
- دسترسی میکروفن، دوربین و صفحه در دستگاه‌های راه دور فقط روی HTTPS فعال است؛ `localhost` برای توسعه استثنا دارد.
- کد دعوت هر اتاق بلند و تصادفی است. هرکس لینک دعوت را داشته باشد می‌تواند وارد شود؛ این نسخه رمز جداگانه یا حساب برای تأیید هویت ندارد.
- پخش‌کنندهٔ همگام از YouTube و لینک مستقیم HTTPS فایل‌های MP4/WebM (و HLS در مرورگرهای سازگار) پشتیبانی می‌کند. هر دستگاه رسانه را مستقیماً از ارائه‌دهنده می‌گیرد و سرور سامیکا فقط فرمان پخش/توقف/جابه‌جایی را همگام می‌کند؛ کیفیت و تأخیر به میزبان ویدئو و اینترنت هر نفر بستگی دارد. بعضی ویدئوهای YouTube اجازهٔ پخش توکار نمی‌دهند و مرورگر ممکن است برای پخش صدا به لمس دکمهٔ پخش نیاز داشته باشد.
- نام کاربری اجباری است، اما هویت کاربر تأیید نمی‌شود؛ هرکس می‌تواند هر نام نمایشی وارد کند.
- تصویر دوربین بدون برش نمایش داده می‌شود تا بزرگ‌نمایی ناخواسته نداشته باشد.

## فایل‌ها

- `index.html` — صفحه و رابط فارسی
- `i18n.js` — ترجمه و راست‌به‌چپ/چپ‌به‌راست برای پنج زبان
- `app.js` — اتاق، WebRTC، چت و اشتراک صفحه
- `server.js` — میزبانی صفحه و سیگنالینگ WebSocket
- `render.yaml` — تنظیم انتشار روی Render
